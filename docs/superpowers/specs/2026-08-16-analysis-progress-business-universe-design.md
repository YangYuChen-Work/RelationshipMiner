# 分析进度舱与业务关系宇宙改造设计

日期：2026-08-16  
状态：已获用户确认，待实施

## 背景

当前分析进行中页面只展示一张窄进度卡，虽然前端已经接收 WebSocket 提供的阶段、进度、消息和诊断数据，但这些信息没有形成可读的实时分析过程。分析完成后的关系图仍使用带同心圆和放射线的“星图”背景，节点布局在大数据量下出现业务数据集分散在外围、实体对象集中在中部的现象，业务人员难以从空间结构理解业务链路。

本次改造保持“Data Meridian Observatory”视觉世界：深石墨用于关系宇宙，矿物象牙用于解释型工作台，铜金用于确认与高价值节点，青绿色用于实时路径与进行中的分析。

## 目标

1. 将分析中页面改造成具有实时阶段感、当前动作和可解释统计的分析舱。
2. 将完成后的关系图改造成“业务主轴 + 局部对象群”的业务关系宇宙。
3. 去除同心圆和放射线背景，保留低对比空间网格作为方向辅助。
4. 节点布局稳定、确定、可复现，并在节点众多时保持分区、间距和关系方向可读。
5. 保留现有 API、后端接口、路由、业务数据模型和图谱交互能力。

## 非目标

- 不修改后端分析算法、WebSocket 消息格式或 API URL。
- 不新增数据库字段或改变关系可靠程度的业务含义。
- 不移除搜索、聚焦、无关节点虚化、拖拽、适应视图、重新布局和导出功能。
- 不把所有实体标签强制展示在总览视角；标签仍由语义缩放策略控制。

## 设计

### 1. 分析舱

`ProgressIndicator` 继续消费 Zustand 中现有的 `currentPhase`、`progressValue`、`progressMessage`、`diagnostics` 和 `selectedTables`，不增加接口字段。

界面分成四个信息层：

1. 状态头部：当前阶段、任务状态、百分比和动态状态标记。
2. 阶段轨道：读取数据、整理对象、梳理关系、寻找候选对象、判断对象关系、生成图谱六个阶段；已完成阶段使用确认色，当前阶段使用实时色，未开始阶段保持低对比。
3. 实时统计：已选数据集、已读取对象、已创建计划、已找到候选关系、已完成判断、已生成强/弱关系。诊断数据缺失时显示稳定的“等待数据”，不显示伪造数字。
4. 解释区域：主文案说明业务阶段，原始技术阶段和后端消息收纳在可展开的技术详情中。

阶段进度只由后端消息驱动。百分比进行 0–100 的边界保护；当阶段消息到达但诊断数据尚未到达时，阶段轨道仍立即更新。

### 2. 业务关系宇宙布局

运行时继续使用现有的 Worker 布局通道和 `GraphLayout` 数据结构，但替换表级锚点策略：

- 表节点按照已知业务流程顺序形成稳定的主轴列；同一阶段的多个数据集在该列中按业务连接度和稳定 ID 排列。
- 未识别流程阶段的数据集按连接度优先、稳定 ID 次序补入剩余主轴位置，避免随机漂移。
- 每个数据集拥有局部对象群区域，实体节点在所属区域内做有边界的均匀分布；实体不再因为全局力导向被吸到整个画布中心。
- 强关系使用更短的目标距离和更高的约束，弱关系保留连接但不挤压主业务链路。
- 断开的多节点组件保持独立的留白边界；单节点组件进入次要分布区，避免遮挡主链路。
- 位置计算使用图谱签名和布局种子保持确定性；用户点击“整理全网布局”时才通过现有 relayout seed 触发另一种稳定排列。

布局完成后继续通过现有的布局过渡动画提交到画布，避免重新布局时节点瞬移。

### 3. 画布背景与视觉层

- 删除 `drawObservatoryBackdrop` 的同心圆和中心放射线绘制。
- 保留低对比网格，作为拖拽、缩放和空间定位辅助，不承担装饰性“宇宙”表达。
- 关系本身承担视觉层级：表关系是结构层，实体关系是业务层，强关系使用更高对比度，弱关系使用虚线和较低透明度。
- 总览不主动制造额外的发光圆环或径向装饰；选中、搜索和聚焦仍以节点/关系状态突出。

### 4. 交互与响应式行为

- 现有搜索、键盘移动、聚焦、拖拽、适应视图和关系检查器继续沿用原 API。
- 选择一个业务对象或关系后，相关节点保持清晰，无关节点继续透明化；新布局只改变空间组织，不改变焦点语义。
- 桌面端保持画布与检查器并列；窄平板切换为画布在上、检查器在下；移动端使用纵向分析舱和可横向滚动的图谱工具条。
- 分析舱在小屏上按状态头部、阶段轨道、统计、详情顺序堆叠，核心进度和错误恢复入口始终可见。

## 数据流与错误处理

```text
WebSocket progress message
        ↓
analysis store: phase / progress / diagnostics
        ↓
ProgressIndicator: stage rail + metrics + technical details

terminal graph snapshot
        ↓
existing LayoutClient / Worker
        ↓
business-lane GraphLayout
        ↓
existing scene, focus, search, renderer, inspector
```

- 分析失败：分析舱保留最后阶段和最后一条可用消息，显示现有错误恢复入口；不把失败误标为完成。
- 分析部分完成：显示可用关系统计和待处理/失败数量，关系宇宙仍可查看现有结果。
- 空图谱：保留空状态说明，画布不绘制伪节点或伪关系。
- 布局失败：沿用现有布局错误状态，保留图谱可用数据和重试/整理入口。
- 诊断字段为空或后端尚未提供：显示“等待数据”而不是填充估算值。

## 实施边界

优先修改以下前端文件：

- `frontend/src/components/ProgressIndicator.tsx`
- `frontend/src/graph/layout.ts`
- `frontend/src/graph/renderer.ts`
- `frontend/src/index.css`

如需补充可测试的阶段映射或布局工具函数，可在现有测试目录增加单元测试；不修改 `frontend/src/api/analysis.ts` 的接口契约。

## 验证计划

1. 组件测试：阶段轨道随进度消息更新；诊断数据为空时不显示伪造统计；技术详情仍可展开。
2. 布局测试：同一图谱结果确定；表节点按主轴分布；实体靠近所属数据集；强关系平均距离小于弱关系；组件边界不重叠；空图和极大图仍输出有限坐标。
3. 渲染测试：总览绘制不再调用同心圆/放射线背景；网格、节点、关系、标签、聚焦虚化和拖拽预览仍正常绘制。
4. 回归验证：TypeScript、Vite build、完整 Vitest、Impeccable layout/type detector、`git diff --check`。
5. 人工检查：生成中、部分完成、失败、7000+ 对象总览、搜索聚焦、窄平板和移动端。

## 验收标准

- 用户能在生成中页面一眼判断当前阶段、完成比例和系统正在做什么。
- 用户能在生成后总览中先看到业务数据集主轴，再看到其所属对象群和跨集关系。
- 画布背景没有多重同心圆或放射线，空间辅助只剩克制网格。
- 大量节点不会全部堆在画布中心，主链路、弱关系和无关组件有清晰层级。
- 原有业务功能、接口和路由全部保持可用。
