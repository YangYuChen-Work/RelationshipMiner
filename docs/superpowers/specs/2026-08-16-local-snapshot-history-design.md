# 本地图谱快照与历史查看设计

日期：2026-08-16  
状态：已获用户确认，待制定实施计划

## 背景

当前项目可以通过 `/api/export/{task_id}` 导出分析结果，但分析任务和结果主要保存在后端进程内存的 `_task_registry` 中。前端完成一次分析后直接进入当前图谱工作台，没有本地历史目录；后端重启、页面刷新或重新开始分析后，用户无法从应用内找回之前的结果。

用户选择的目标场景是：单人、单机、本地使用。用户希望手动保存某次分析结果，之后从历史列表重新打开，并恢复上次的探索状态。

## 目标

1. 用户可以手动保存已完成的关系图谱。
2. 保存结果写入当前浏览器的 IndexedDB，不增加后端持久化接口。
3. 用户可以查看、搜索、打开、重命名、删除历史图谱。
4. 打开历史图谱时恢复完整图谱、原始字段值、布局和视图状态。
5. 用户可以通过“保存”更新当前快照，通过“另存为”创建新快照。
6. 当前图谱和历史图谱都能导出 JSON，历史图谱不依赖后端 `task_id`。
7. 不保存数据库密码、API Key 或其他连接凭据。

## 非目标

- 云端同步、多人共享或跨浏览器同步。
- 标签、备注、收藏和个人知识库功能。
- 两个快照之间的差异对比。
- 手动创建、删除、确认或忽略关系。
- 自动保存。
- 打开历史图谱后自动重新连接数据库或重新执行 AI 分析。
- 让历史快照随着源数据库自动刷新。

## 用户体验

### 保存当前图谱

分析完成后，当前图谱显示“未保存”状态。用户点击图谱工具栏中的“保存图谱”，打开名称输入窗口。名称为必填项，默认建议使用“分析图谱 + 日期时间”。保存成功后显示“已保存”和保存时间。

保存内容包括完整图谱和当前探索状态，包含原始字段值，因此保存窗口需要明确提示：数据仅保存在当前浏览器，但清除网站数据可能删除本地历史。

分析进行中、没有图谱结果或图谱载入失败时，保存按钮不可用。

### 历史图谱列表

左侧工作台导航新增“历史图谱”入口。列表按保存时间倒序展示，每条记录至少包含：

- 图谱名称
- 保存时间
- 来源数据库名称
- 分析表数量
- 节点数量
- 关系数量
- 打开、重命名、删除操作

列表支持按名称搜索。没有历史记录时显示空状态，并引导用户先完成一次分析后保存。

### 打开与编辑保存

打开历史图谱后，用户仍可以搜索节点、缩放、拖拽、筛选关系、切换孤立节点显示并查看详情。这些变化不会自动写入 IndexedDB；变化发生后显示“有未保存更改”。

- “保存”：更新当前快照。
- “另存为”：打开名称输入窗口，创建一条新的快照记录，并将新记录设为当前活动快照。
- 用户准备重新分析、离开当前图谱或打开另一条记录时，如存在未保存更改，显示未保存提醒。
- 删除历史图谱必须二次确认。

## 快照数据模型

每条快照使用版本化结构：

```ts
interface GraphSnapshot {
  schemaVersion: 1;
  id: string;
  name: string;
  savedAt: string;
  analysisConfig: {
    databaseName: string | null;
    metadataRevision: string | null;
    selectedTables: Array<{
      name: string;
      selectedFields: string[];
    }>;
    selectionMode: "natural" | "manual";
    selectionSource: "ai" | "manual" | "mixed";
    naturalLanguageInput: string;
  };
  result: {
    graph: SemanticGraphData;
    analysisStatus: "complete" | "partial" | "failed";
    diagnostics: AnalysisDiagnostics | null;
    warnings: string[];
  };
  viewState: {
    nodePositions: Record<string, { x: number; y: number }>;
    viewport: { x: number; y: number; scale: number };
    confidenceThreshold: number;
    showIsolatedNodes: boolean;
    selectedNodeId: string | null;
    selectedEntityEdgeId: string | null;
    selectedTableEdgeId: string | null;
  };
}
```

其中 `SemanticGraphData` 保留节点详情所需的完整原始字段值。快照只保存安全的数据库名称和分析元数据，不保存连接地址中的凭据、数据库密码、API Key、WebSocket 实例或后端任务句柄。

如果某些运行时状态无法恢复，则只恢复持久化定义的图谱和视图状态，不把临时网络连接或正在运行的任务写入快照。

## 本地存储与数据流

IndexedDB 数据库建议命名为 `ai-graph-local`，使用 `snapshots` object store。每条记录以 `id` 为主键，并建立 `savedAt` 和 `name` 索引，支持时间排序和名称搜索。

保存流程：

```text
GraphWorkbench 当前状态
        ↓
收集 graph、analysisConfig、layout、viewport 与筛选状态
        ↓
构造并校验 GraphSnapshot
        ↓
IndexedDB snapshots.put()
        ↓
更新当前快照 ID 与“已保存”状态
```

打开流程：

```text
历史列表选择快照
        ↓
IndexedDB snapshots.get()
        ↓
校验 schemaVersion 与必要字段
        ↓
恢复 Zustand 图谱、分析状态和视图状态
        ↓
进入 GraphWorkbench，本地快照模式
```

当前实时分析结果仍可调用后端导出接口。历史图谱由于没有后端 `task_id`，需要由前端根据 `GraphSnapshot` 生成 JSON Blob 并下载；导出内容应包含快照版本、名称、分析配置、完整结果和视图状态。

## 前端模块边界

建议新增或扩展以下职责边界：

- `snapshotStorage`：只负责 IndexedDB 初始化、CRUD、索引查询和存储错误映射。
- `snapshotSerializer`：只负责从当前 Zustand/GraphWorkbench 状态生成快照，以及校验和恢复快照。
- `HistoryGallery`：只负责历史列表、名称搜索和记录操作。
- `SnapshotNameDialog`：只负责保存/另存为名称输入和保存确认。
- `SaveStateIndicator`：显示已保存、未保存和保存失败状态。
- `analysis` store：持有当前快照 ID、快照名称、保存状态，并暴露保存、打开、重命名、删除、另存为操作。

现有 `GraphCanvas` 或 `GraphWorkbench` 需要通过明确的状态接口提供节点坐标和 viewport；不要依赖无法访问的局部组件状态来保存布局。恢复快照时也应通过同一接口注入布局和视图状态。

## 错误处理

- IndexedDB 不可用：显示“本地保存不可用”，提供 JSON 下载作为替代。
- 存储空间不足：显示“本地空间不足”，建议导出后删除旧快照。
- 快照校验失败：不改变当前图谱，提示该历史记录无法打开。
- 未来版本无法识别：保留记录但禁止加载，显示格式版本提示。
- 删除失败：保留列表项并显示可重试的错误，不伪装成删除成功。
- 保存失败：保持“未保存”状态，当前图谱和用户正在进行的探索不丢失。
- 打开历史快照：不发起数据库查询，不重连 WebSocket，不显示为正在分析。

## 测试与验证

### 单元测试

- 快照序列化包含完整图谱、原始字段值、分析配置和视图状态。
- 快照反序列化后可以恢复节点、关系、布局、viewport、筛选值和选中对象。
- 缺少必要字段或错误 `schemaVersion` 时校验失败。
- 快照名称搜索和按保存时间排序正确。
- 保存、更新、另存为、重命名和删除对应正确的 IndexedDB 记录。

### 组件测试

- 保存窗口可以创建名称并显示保存成功状态。
- 保存失败时显示错误和 JSON 备选操作。
- 历史列表展示空状态、记录摘要、搜索结果和删除确认。
- 打开历史快照后显示本地快照状态，不依赖 `taskId`。
- 修改视图后显示未保存状态；保存更新当前记录，另存为创建新记录。
- 历史图谱导出使用本地快照内容，实时图谱导出继续保持现有行为。

### 集成验证

1. 完成一次分析并手动保存。
2. 刷新浏览器后进入历史列表，确认记录仍存在。
3. 打开记录，确认节点详情中的原始字段值可查看。
4. 确认布局、缩放、关系筛选和选中对象恢复。
5. 修改筛选条件后刷新，确认未保存更改不会被错误持久化。
6. 使用“保存”更新当前记录，使用“另存为”创建独立记录。
7. 删除记录并确认二次确认和列表更新。
8. 模拟 IndexedDB 失败或空间不足，确认当前图谱仍可导出 JSON。

## 验收标准

- 用户可以明确控制何时保存，不会因为一次分析自动产生历史记录。
- 页面刷新或后端重启后，已保存的本地图谱仍可从历史列表打开。
- 打开历史图谱不需要数据库可用，也不会重新执行分析。
- 图谱内容和用户上次的探索现场能够恢复。
- 保存、更新、另存为、重命名、删除、搜索和导出行为清晰可预测。
- 敏感凭据不会进入快照；原始字段值的本地保存范围会被明确告知。
- 本地存储失败时，用户仍有 JSON 导出恢复路径。
