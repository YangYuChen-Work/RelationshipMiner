# 图谱节点模糊定位设计

## 目标

将图谱画布右上角的实体定位功能从单一精确匹配升级为可复用的模糊搜索：用户输入一个或多个关键字后，系统定位命中的节点；当存在多个命中时，可通过“下一个”依次循环跳转。

## 范围

- 搜索仅作用于当前图谱中可展示的实体节点，不修改后端接口、图谱数据或全局 Zustand store。
- 搜索词按空白字符分隔；任意一个非空关键字匹配即可命中（OR 语义）。
- 匹配忽略大小写、首尾空格、连续空格差异和全半角差异。
- 匹配节点的业务显示名称和对象分类名称，以兼容用户从不同业务术语进行定位。
- 搜索开始、关键词改变或清空时，重置当前位置；不会改变筛选、隐藏孤立节点、关系阈值或手动布局。

## 交互

1. 用户在现有“查找实体”输入框键入关键字。多个关键字用空格分隔。
2. 提交搜索（回车或点击“定位”）时：
   - 有命中：跳转到稳定排序后的第一个节点，选中它并更新详情面板。
   - 无命中：显示“未找到匹配节点”，不执行跳转。
3. 有多个命中时，显示当前位置和总数（如 `1 / 3`）以及“下一个”按钮。
4. 点击“下一个”时，循环跳转到下一项；从最后一项回到第一项。
5. 只有一个命中时，计数显示 `1 / 1`，仍可点击“下一个”重新聚焦该节点；无命中时按钮禁用。

## 方案选择

采用“本地派生匹配列表 + 当前位置索引”方案：`GraphCanvas` 持有搜索词和当前索引，基于当前投影图谱以及既有展示名称索引，用 `useMemo` 计算稳定、去重的命中节点列表。

未采用每次点击重新检索，因为它无法可靠展示当前位置，并会在图谱状态变化时产生不透明的跳转顺序。未采用全局 store，因为搜索状态只服务画布工具条，跨组件共享会增加无关耦合。

## 实现边界

- 在图谱辅助模块中抽取纯函数，负责关键词规范化、OR 匹配、稳定排序和下一索引计算；组件只管理输入与触发聚焦。
- 节点排序优先按业务显示名称，其次按节点 ID，确保同一图谱状态中导航顺序可预测。
- 节点聚焦沿用现有 `requestNodeFocus` 流程，因此 Canvas 平移、选中状态、关系聚焦和详情面板继续保持一致。
- 图谱投影变化时，重新计算命中结果；若当前节点仍在列表中则保留其位置，否则回到首个结果。

## 错误处理与可访问性

- 空输入不显示匹配计数，定位按钮不会执行跳转。
- 无匹配时通过状态文本反馈，并禁用“下一个”。
- 匹配计数使用简短、可读的文本，按钮具有明确的可访问名称。
- 节点名称缺失时，使用现有展示名称回退规则；不因异常数据导致搜索或导航崩溃。

## 测试与验收

- 纯函数测试：多个词采用 OR、大小写/空白/全半角规范化、稳定排序、循环索引和空结果。
- 组件测试：提交搜索跳转第一个命中；“下一个”依次跳转并循环；显示正确的 `当前位置 / 总数`；无命中禁用导航并显示提示。
- 回归：现有单个精确定位、键盘提交和画布选中/详情联动继续通过。
- 运行前端测试、lint 和生产构建验证。

## 成功标准

用户输入任意一个或多个关键词后，能定位到任意命中的图谱节点；当有多个节点命中时，连续点击“下一个”能按稳定顺序遍历所有命中并回到首项，且每一次跳转都在画布和详情面板中反映当前节点。
