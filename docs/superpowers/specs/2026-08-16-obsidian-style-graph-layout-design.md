# Obsidian 式关系图布局与动效设计

## 背景

当前关系图虽然保留了实体、表级关系、搜索、拖拽、缩放和详情面板，但默认布局仍受数据表业务车道、表锚点、组件锚点以及大图格点打包影响。结果是关系节点被拉到很远的位置，画布出现跨越大面积空白的长线，节点之间的关系轮廓难以阅读。

本次改造只调整图谱的空间组织和视觉反馈，不改变关系分析、业务展示字段或节点旁的具体数据标注。目标是让默认图谱具备类似 Obsidian Graph View 的自然星云轮廓：有关系的对象形成紧凑团块，关系强弱影响距离和视觉权重，悬停与选中时能快速看清一跳邻接关系。

## 用户约束

- 默认视图展示所有有关系的对象。
- 孤立对象继续默认隐藏，并保留现有开关用于显示。
- 节点旁的具体数据标注必须保留。
- 不改变现有主名称、副标识、重名编号、标签位置、搜索文本和详情展示文本。
- 不删除现有搜索、拖拽、缩放、适应视图、重新整理和详情面板能力。
- 附件截图仅作为视觉参考，不作为额外操作指令。

## 目标

1. 消除由表格车道和固定表锚点造成的跨画布长线。
2. 让强关系节点自然靠近，弱关系节点保持适度距离。
3. 让连通分量形成紧凑、可辨识的自然团块，而不是规则网格或等距分栏。
4. 保留业务节点标注，并使标注在新布局下仍能通过现有碰撞与语义缩放规则绘制。
5. 用轻量的布局过渡、聚焦光晕和关系脉冲增强交互反馈。
6. 在当前 Canvas + D3 + Web Worker 架构内完成，不引入新的图可视化框架。

## 非目标

- 不修改后端关系发现、置信度判断或公开图谱协议。
- 不重新定义 `display_name`、`display_code` 或关系业务文案。
- 不把节点改为只显示圆点，也不把具体数据标注改成只在悬停时出现。
- 不实现节点增删、关系编辑或社区编辑。
- 不用 WebGL 替换现有 Canvas 渲染。
- 不对当前工作树中与本设计无关的已有修改做清理或重写。

## 方案选择

采用统一的自由力导向星云布局。

未采用按数据表分区的“业务簇 + 簇内布局”，因为它会继续给不同数据表施加明显的空间分隔，容易重现当前的远距离岛状分布。未采用中心层级布局，因为它会把全局轮廓过度压缩到少数中心节点，降低对整个业务网络的观察价值。

## 布局设计

### 输入范围

布局继续消费前端当前已经投影后的图谱：默认只包含有可见关系的实体节点和实体边。`showIsolatedNodes` 打开时才将孤立节点加入布局。表节点和表边保留在布局结果中，以维持现有详情、图例和语义缩放能力，但不再作为实体节点的主定位锚点。

### 节点位置

- 所有可见实体节点进入同一个 D3 力导向系统。
- 节点初始位置使用基于图签名的稳定伪随机种子，保证同一份数据和同一视图请求产生可复现的初始形态。
- 实体边使用关系权重映射目标距离与弹簧强度：强关系更短、更有约束；弱关系更长、更轻。
- 使用带有节点碰撞半径的排斥力，避免节点与其具体数据标注大面积挤在同一位置。
- 只保留很弱的来源表/业务类型聚类力，用于保持轻微的语义邻近；该力不能把节点锁回表格车道。
- 连通分量使用紧凑的确定性初始偏移，并在全局力导向阶段共同松弛，避免组件之间形成过大的固定空白。
- 布局完成后只做最小限度的重心校正和碰撞修正，不再进行规则矩形格点打包。
- 拖拽节点后继续沿用现有固定点与边路由逻辑。

### 大图降级

当节点数量较大时，仍保留当前的确定性降级和 Worker 执行边界，但降级目标改为“紧凑的可读星云”而不是“表拥有的格点”。大图只减少不影响主轮廓的低优先级力计算，不减少默认可见的有关系实体节点，也不改变标注数据。

### 表节点与表边

表节点、表边和来源颜色继续保留。默认实体图中，表级关系只作为低对比背景层，不参与实体节点的主要定位；在语义缩放或聚焦场景中仍可通过现有逻辑显示，以维持技术追踪和详情能力。

## 标注与业务展示

本次不改动以下模块或规则：

- `businessPresentation` 的主名称、副标识和重名处理。
- `scene.ts` 中的实体标签生成、语义缩放层级与标签文本。
- `renderer.ts` 中标签的主行/副行绘制和现有碰撞避让策略。
- 搜索、键盘命中、详情面板使用的展示名称。

新布局只提供新的世界坐标。节点旁的具体数据标注继续以当前节点为锚点跟随移动；焦点节点仍然可以按照当前逻辑提升标签可见性，不能被新的动效隐藏。

## 视觉与动效设计

### 默认关系层

- 实体关系是主要视觉层，使用低对比但连续可追踪的曲线。
- 表级关系保持更低不透明度，不与实体边争夺注意力。
- 关系线宽继续按普通、聚焦和选中状态分层，而不是所有关系同等高亮。

### 聚焦状态

悬停或选中实体节点时：

- 当前节点显示强调描边和柔和光晕。
- 一跳邻居与关联边提升不透明度和线宽。
- 无关节点和关系淡出，但保留足够的轮廓，不让用户失去全局位置感。
- 关联边可使用轻量的流动虚线偏移或短脉冲，表达关系正在被聚焦；不使用高频、持续的大面积动画。

### 布局过渡

- 首次布局、重新整理和过滤后重新布局使用约 500–700ms 的缓动过渡。
- 过渡只更新 Canvas 绘制所需的坐标和透明度，避免逐帧重建 React 组件树。
- `prefers-reduced-motion: reduce` 下跳过或缩短过渡与关系脉冲。
- 搜索定位与适应视图继续使用平滑的缩放/平移反馈。

## 模块边界

### `frontend/src/graph/layout.ts`

负责统一自由力导向、稳定种子、关系权重映射、碰撞处理和确定性居中。删除或绕开造成车道化和格点化的主路径，但保留公开布局类型、Worker 调用边界和拖拽使用的布局结构。

### `frontend/src/graph/scene.ts`

继续负责语义缩放、实体/表边可见性、曲线几何和现有标签生成。只在必要时调整表级层的显示权重，不改变业务展示文本。

### `frontend/src/graph/renderer.ts`

继续负责 Canvas 绘制和聚焦分层。新增或调整轻量焦点光晕、关系脉冲参数，确保绘制仍以 `requestAnimationFrame` 合并，且不影响命中测试。

### `frontend/src/components/GraphCanvas.tsx`

继续负责 D3 缩放、拖拽、布局过渡和动画帧生命周期。布局动画使用现有插值机制扩展，动效必须在组件卸载、重新布局和减少动态效果模式下正确清理。

## 数据流

1. 分析结果进入现有 Zustand store。
2. `projectGraph` 按当前开关过滤孤立节点。
3. Layout Worker 使用投影后的图谱计算自由力导向坐标。
4. `GraphCanvas` 对新旧坐标做平滑插值。
5. `buildScene` 使用原有业务展示索引生成节点和标签命令。
6. Canvas 按背景、关系、节点、具体数据标注、焦点高亮的顺序绘制。
7. 悬停、选中、搜索和拖拽只改变绘制状态或局部坐标，不重新运行不必要的布局。

## 验收与测试

### 布局单元测试

- 同一图谱和种子产生稳定坐标。
- 有关系节点不会被表格车道强行拉开。
- 强关系的平均距离小于弱关系。
- 连通分量之间保持最小间距，但不出现规则矩形排列。
- 所有坐标有限，节点和边 ID 完整保留。
- 过滤孤立节点只改变布局输入范围，不改变业务展示文本。

### 渲染与交互测试

- 节点主名称、副标识和重名编号保持与改造前一致。
- 标签继续跟随节点移动，搜索和详情使用同一展示字段。
- 悬停时一跳邻居、关系线和焦点节点正确高亮。
- 重新布局使用过渡，取消或卸载时不残留动画帧。
- 减少动态效果模式不依赖过渡完成即可交互。
- 拖拽、适应视图、缩放和命中测试继续有效。

### 视觉验收

在 1920×1080、1366×768 和窄屏工作台上，使用 20 节点、200 节点和当前大图数据检查：

- 整体轮廓为自然星云团块，没有大量跨画布长线。
- 强关系局部结构清晰，弱关系不会压过节点标注。
- 节点旁的具体数据标注仍然保留且不被新动效遮挡。
- 悬停/选中后焦点关系一眼可辨，同时保留全局上下文。
- 大图不会因默认布局再次扩散到不可读的空旷区域。
