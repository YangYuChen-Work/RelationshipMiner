# 语义关系图星云布局与节点呈现设计

## 目标

修复关系图谱工作台的三个前端展示问题：

1. 初始视图中的实体节点缺少可识别的实例信息，部分数据会让所有节点只显示 `0`。
2. 当前同心圆式表分组与跨组直线关系叠加后形成毛线团。
3. 悬停节点只增加描边，没有突出相关节点和关系，也没有弱化无关内容。

最终效果以 Obsidian 风格的力导向星云为视觉参照：节点自然散列、关联节点局部成团、团块边界不规则、跨团桥接节点清晰，同时保持现有深色专业数据工作台的产品语境。

本次只修改前端图谱的布局、呈现和交互，不修改后端关系发现算法或公开数据协议。

## 设计判断

- 页面类型：面向数据分析人员的专业关系图谱工作台。
- 改造模式：保留现有信息架构和深色视觉语言的针对性演进。
- `DESIGN_VARIANCE`：4。整体结构稳定，但图谱本体允许有机分布。
- `MOTION_INTENSITY`：4。布局收敛和状态切换有适度动画，不加入装饰性运动。
- `VISUAL_DENSITY`：8。信息密度高，依靠语义缩放和聚焦状态控制噪声。
- 技术基础：沿用 React、TypeScript、D3、Canvas、Web Worker 和 Zustand，不引入新的设计系统或图谱依赖。

## 根因

### 初始节点没有有效信息

`scene.ts` 仅在缩放比例 `k >= 1.2` 时生成实体标签，但初次“适应画布”经常产生更小的比例，因此初始画面只剩节点圆点。

后端 `display_name` 使用第一个非空分析字段。当前端选择的首个字段是数值状态位时，多个实体可能都得到 `0`。现有前端没有基于 `dimensions`、`class_name` 和实体 ID 的语义回退。

### 图谱形成毛线团

`layout.ts` 将每张表的实体等角度放置在同心圆上，再将所有实体关系绘制为直线。布局没有利用实体关系调整位置，因此强关联节点不会自然靠近，跨表关系会贯穿整个画布。

当前场景还可能同时显示表聚合关系和实体关系。两个粒度的连线叠加会进一步放大视觉噪声。

### 悬停没有关系聚焦

现有悬停状态只记录单个实体 ID，并为该节点增加白色描边。场景中没有邻接集合，也没有按相关性调整节点、标签和关系的透明度。

## 方案选择

采用“确定性混合聚类力导向布局”。

未采用纯分层布局，因为当前图允许循环、多种关系和跨表连接，分层后会产生大量长回边。

未采用“同心圆加边捆绑”，因为它只能遮掩交叉，不能让真实关联节点自然靠近，并且会降低具体关系的可点击性和方向可读性。

## 星云布局模型

### 总体原则

关系是节点位置的主要依据，表归属是柔性聚类约束。布局不得使用同心圆、规则圆环、等角度排列或规则网格作为正常结果。

### 初始位置

- 根据图数据生成固定随机种子。
- 使用实体 ID 和表 ID 的稳定哈希生成初始散列位置。
- 相同数据与相同布局版本产生稳定结果，避免刷新后无意义跳动。
- “重新布局”可以改变布局种子，使用户获得另一种合理排列，但结果仍需满足聚类和碰撞约束。

### 力模型

- 强关系使用更短的期望距离和更强的连接力。
- 弱关系使用更长的期望距离和更弱的连接力。
- 每张表拥有隐形柔性引力中心，使同表实体大致聚集。
- 表引力不能覆盖强跨表关系。跨表桥接节点允许停留在两个团块之间。
- 节点使用排斥力形成自然留白。
- 碰撞范围同时考虑节点标记和两行标签的近似边界。
- 不同连通分量使用分量级分离力，大分量靠近主视区，小分量分布在外围，并保留明显间距。
- 无关系实体按来源表在对应团块外围散列，不堆积在画布中心。

### 执行位置与生命周期

- 力模拟在现有 Web Worker 中运行。
- 模拟使用固定迭代预算并同步收敛，不将逐帧模拟状态发送回主线程。
- 初次加载和用户触发“重新布局”时重新计算。
- 缩放、平移、悬停、选中和置信度筛选不重新计算布局。
- 用户拖动节点后，该节点保持固定，直至再次执行“重新布局”。
- 初次布局完成后自动适应画布。

## 节点信息设计

### 常驻两行标签

每个实体节点使用紧凑的“节点标记加两行文字”结构：

- 主行显示实例名称或业务编码。
- 副行显示类名短称或来源表名，并显示可见关系数量。
- 节点颜色继续表达来源表，选中强调色保持统一。

### 主标题选择

前端从已有实体数据中生成展示标题，不修改后端协议。

按以下顺序选择：

1. 从 `dimensions` 中优先选择字段名带有 `name`、`title`、`label`、`code`、`number`、`no`、`id`、`serial` 或 `model` 语义的有效值。
2. 使用有效的 `display_name`。
3. 使用实体 ID 中主键部分的可读片段。
4. 最后使用类名短称加 ID 片段。

以下值不能单独作为有效标题：

- 空字符串、空白、`null`、`undefined`。
- 单独的 `0` 或 `1`。
- 布尔值。
- 只有状态含义且无法区分实例的值。

字符串需要限制显示长度并使用省略号。完整内容通过悬停聚焦和详情面板访问。

### 语义缩放

- 工作级缩放显示主行和副行。
- 进一步缩小时先隐藏低优先级节点的副行，保留主行。
- 极端概览级才隐藏低优先级实体标签。
- 悬停或选中的节点始终显示完整两行信息。
- 初始缩放应尽可能进入工作级，优先保证实例可识别。

## 关系呈现

### 分层显示

表聚合关系和实体关系不在同一缩放级别同时以完整强度显示：

- 概览级以表团块和聚合关系为主，实体关系降低存在感。
- 工作级以实体关系为主，表聚合关系淡出。
- 细节级补充实体关系文字和方向箭头。

### 线路

- 普通关系使用稳定的轻微弧线，减少直线完全重叠。
- 同一对节点间的平行关系按稳定序号向两侧偏移。
- 多种关系已经合并在同一实体边时，继续使用一条边和组合标签。
- 关系从节点及标签的外侧边界出发，不穿过节点文字。
- 强关系使用较实、较亮的线。
- 弱关系使用低对比虚线。
- 自环关系绘制为节点旁的小弧环。
- 聚焦关系最后绘制，确保不会被背景关系覆盖。

### 标签与方向

- 概览和工作级不同时铺满全部关系文字。
- 悬停或选中节点后显示相关关系标签。
- 关系标签使用紧凑深色底板，与连线分离。
- 有方向的关系在聚焦或细节级显示箭头。
- 未聚焦状态不展示密集箭头。

完整边捆绑不属于本次范围。首轮修复优先依靠关系驱动布局、语义缩放和聚焦降噪提高可读性。

## 悬停与选择

### 悬停

图数据或置信度阈值变化时，前端以可见实体关系构建邻接索引。

鼠标悬停实体节点时：

- 当前节点、一跳邻居和关联关系保持完整亮度。
- 相关关系加粗并显示标签。
- 无关实体节点和标签降至约 16% 不透明度。
- 无关实体关系降至约 6% 不透明度。
- 无关表节点与聚合关系保持较低但可辨识的上下文亮度。
- 悬停离开后恢复默认状态。

悬停只聚焦一跳邻居，不递归高亮整个连通分量，避免大型图谱再次出现大面积同时高亮。

### 选择

- 单击实体节点固定当前聚焦状态并打开详情栏。
- 单击另一个实体切换选择。
- 单击空白处取消选择。
- 悬停临时覆盖视觉聚焦，但不清除已选择实体。
- 画布继续支持键盘聚焦和 Enter、Space 选择。

动画只用于透明度、线宽感知和状态切换，并遵循 `prefers-reduced-motion`。

## 组件与数据流

### 展示信息模块

新增独立的实体展示信息模块，输入 `EntityNodeData` 和可见关系数，输出主标题、副标题与完整辅助文本。节点绘制、搜索、键盘朗读和详情摘要共享同一套结果，避免不同入口显示不同名称。

### 布局模块

`layout.ts` 负责紧凑布局输入、固定种子、力模型、分量分离和标签碰撞近似。`layout.worker.ts` 负责执行并返回稳定坐标。

### 场景模块

`scene.ts` 负责：

- 语义缩放层级。
- 曲线关系几何和箭头信息。
- 节点与标签绘制命令。
- 可见关系邻接索引。
- 聚焦状态需要的节点和关系集合。

### 画布组件

`GraphCanvas.tsx` 负责：

- Canvas 绘制顺序。
- D3 缩放与平移。
- 节点拖动。
- 悬停和选择事件。
- 将聚焦状态应用为颜色、透明度和线宽。

布局计算不进入 React 渲染循环。悬停不重新运行布局，也不逐帧重渲染组件树。

## 性能

- 邻接索引以 `O(V + E)` 构建，仅在图或关系筛选结果变化时更新。
- 悬停查询使用集合查找。
- 多次绘制请求合并到单个 `requestAnimationFrame`。
- Worker 仅返回必要的节点和关系坐标。
- 置信度筛选复用布局坐标。
- 屏幕空间标签碰撞和可见区域裁剪限制实际文字绘制量。
- 继续限制极端缩放范围和无效几何，避免 Canvas 数值异常。

## 错误与降级

- Worker 布局失败时保留分析结果并显示可重试提示。
- 降级布局使用基于稳定哈希的确定性散列分组，不使用圆环布局。
- 单个节点缺少展示字段时使用 ID 回退，不丢弃节点。
- 单条关系缺少方向或标签时仍绘制基础关系线。
- Canvas 失败时保留现有错误边界、导出和重新分析能力。
- 空图和无关系图继续使用现有明确状态；无关系节点按来源表自然散列。

## 测试

### 单元测试

- `display_name` 为 `0` 时能从有意义的维度或 ID 生成主标题。
- `0`、`1`、布尔值、空值和状态字段不会独占主标题。
- 标题选择在不同字段顺序下保持确定性。
- 同一图和种子产生相同坐标。
- 所有坐标有限且节点 ID 保持完整。
- 布局结果不满足规则圆环特征。
- 强关联节点的平均距离小于无关联节点。
- 不同连通分量之间具有最小间距。
- 标签碰撞范围没有明显重叠。
- 筛选置信度不会改变节点坐标。
- 邻接索引只返回一跳邻居和相关关系。
- 悬停状态正确计算相关与无关元素。
- 表聚合关系和实体关系在语义缩放层级间正确切换。
- 曲线关系、自环、平行关系和方向箭头生成稳定几何。

### 组件测试

- 初始画布无需点击即可绘制有效实例标题。
- 悬停节点时相关节点和关系高亮，无关内容弱化。
- 指针离开后恢复默认样式。
- 单击节点固定聚焦并打开详情栏。
- 单击空白处清除选择。
- 重新布局触发 Worker，筛选和悬停不触发 Worker。
- 减少动态效果模式下不依赖过渡完成交互。

### 浏览器视觉验收

使用至少 20 节点和 200 节点两个代表性图谱，在以下视口检查：

- 1920×1080。
- 1366×768。
- 窄屏工作台。

每个场景检查初始视图、悬停态、选中态、置信度筛选和重新布局。验收截图应确认：

- 没有全部节点只显示 `0`。
- 没有同心圆、规则圆环或等角度排列。
- 图谱呈现不规则星云团块。
- 一跳悬停聚焦清晰。
- 表关系和实体关系没有同时满强度叠加。
- 节点两行标签没有大面积重叠。

## 非目标

- 不修改后端关系发现和 `display_name` 生成逻辑。
- 不修改公开 API 数据结构。
- 不实现完整边捆绑。
- 不实现社区编辑、节点增删或关系编辑。
- 不引入 WebGL 或新的图可视化框架。
- 不改变工作台路由、工具栏主要操作和详情面板信息架构。
