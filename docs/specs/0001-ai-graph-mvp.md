# 0001 — AI 驱动关系图谱 MVP 1.0

## Problem Statement

用户拥有存储在 MySQL 数据库中的 Java 项目数据（10 张以内表，每表约 1000 行）。不同表的数据之间可能存在隐含的关联——外键、值相等、语义匹配、继承关系——但这些关联分散在 schema 元数据、字段值、以及 Java 类的命名中，缺乏一个直观的工具来发现和探索。

用户需要：选择感兴趣的表和字段，让 AI 自动分析并挖掘所有可能的关系，最终在类似 Obsidian 的交互式力导向图谱中探索这些关联。

## Solution

一个 Web 应用，用户在前端勾选 MySQL 表与字段，系统对全量数据执行笛卡尔积级别的分析——Schema 层（外键）、数据层（值精确相等）、语义层（AI 推断字段匹配+算法选择）——将发现的关系以合并标签的边呈现在力导向图谱上。图谱支持悬停高亮、单击局部导航、双击详情面板、滑块按置信度筛选关系。分析结果可导出为 JSON 完整快照。

## User Stories

### 数据库连接

1. 作为一个数据分析师，我想要系统自动读取后端配置的 MySQL 数据库，以便打开页面即可看到可用的表列表
2. 作为一个数据分析师，当数据库连接失败时，我想要看到友好的错误提示和排查建议（如"请检查 .env 文件中的数据库配置"），以便我知道如何修复

### 数据范围选择

3. 作为一个数据分析师，我想要在前端看到所有可用的数据库表，以便我选择要分析的表
4. 作为一个数据分析师，我想要勾选表（最多 10 张），以便我定义分析的数据边界
5. 作为一个数据分析师，当我选中表后，我想要看到每张表的所有字段，以便我选择参与分析的字段
6. 作为一个数据分析师，我想要系统自动识别并标记 class_name 相关字段（`class_name`、`className`、`class`），以便我不需要手动查找
7. 作为一个数据分析师，我想要勾选字段（通常 2-4 个），并且允许全选所有字段，以便我灵活控制分析范围
8. 作为一个数据分析师，当某张表缺少 class_name 字段时，我想要该表仍能正常参与其他分析（FK、值相等、语义匹配），只是跳过继承关系发现

### 分析执行

9. 作为一个数据分析师，当我点击"开始分析"后，我想要通过 WebSocket 实时看到分析进度（数据读取 → Schema 分析 → AI 决策 → 关系计算 → 图谱生成），以便我知道系统没有卡死
10. 作为一个数据分析师，当分析在 3 分钟内超时时，我想要看到提示"分析超时，建议减少表数量或行数后重试"，以便我知道如何调整

### AI 决策

11. 作为一个数据分析师，我想要 AI 自动判定不同表中哪些字段语义相同（如 `user_email` ≈ `contact_email`），基于表名+字段名的组合上下文做区分（如 `users.name` ≠ `products.name`），以便系统不漏掉隐含的字段关联
12. 作为一个数据分析师，我想要 AI 为模糊匹配选择合适的相似度算法，以便值的精确度判断是智能而非一刀切的
13. 作为一个数据分析师，当 DeepSeek API 不可用时，我想要看到友好提示"AI 服务暂不可用，请稍后重试"，而不是一个白屏或崩溃

### 图谱呈现

14. 作为一个数据分析师，我想要看到所有数据记录以节点的形式展示，节点颜色按来源表区分、大小按关联度数区分、图标按 class_name 类型区分，以便我一眼看懂图的结构
15. 作为一个数据分析师，我想要已发现的关系以带有方向箭头的边呈现，边上标注关系类型的文字说明（如"外键关联"、"值相等(email)"、"继承: VIPCustomer → Customer"），以便我理解每条边的含义
16. 作为一个数据分析师，当两条记录之间存在多种关系类型时，我想要它们合并为一条边、标签拼接展示，以便图谱不被大量平行边淹没
17. 作为一个数据分析师，我想要图谱使用力导向布局，并且我可以缩放和拖拽，以便我自由探索图谱的不同区域
18. 作为一个数据分析师，我想要所有节点正常显示（包括没有关系的孤立节点），不被隐藏或折叠

### 图谱交互

19. 作为一个数据分析师，当我鼠标悬停在一个节点上时，我想要该节点及其所有关联节点（不限深度）高亮显示，以便我快速看到这条记录的关系链
20. 作为一个数据分析师，当我单击一个节点时，我想要以该节点为中心看到其局部关联图谱，以便我聚焦探索
21. 作为一个数据分析师，当我双击一个节点时，我想要看到该数据记录的所有字段原始值以及它关联的节点列表，以便我追溯到源数据
22. 作为一个数据分析师，我想要通过一个连续滑块（0.0–1.0）按置信度阈值筛选边的显示与隐藏，以便我只看到我关心的关系
23. 作为一个数据分析师，当分析完成后未发现任何关系时，我想要看到空状态提示"未发现任何关系，建议调整表/字段选择"以及仅节点的散落图谱，以便我知道数据已被分析但无关联

### 保存与导出

24. 作为一个数据分析师，我想要将当前分析结果导出为 JSON 文件（包含图谱数据+原始数据+分析配置+布局坐标），以便我离线查看或分享
25. 作为一个数据分析师，我想要在后续版本中导入已导出的 JSON 文件恢复图谱，以便我延续之前的分析

## Implementation Decisions

### 架构

- **Web 前后端分离**：React 前端与 Python FastAPI 后端通过 HTTP REST + WebSocket 通信
- **AI 引擎**：DeepSeek API，通过 OpenAI 兼容 SDK 调用
- **数据库**：MySQL（MVP 仅支持 MySQL），后端 SQLAlchemy 反射 schema 元数据

### 分析流水线（5 阶段）

1. **数据读取**：SQLAlchemy 执行 SELECT 拉取选中表与字段的全量数据
2. **Schema 分析**：解析外键约束、索引、字段类型元数据；提取 class_name 字段的 Java 类全限定名
3. **AI 决策**：调 DeepSeek API，传入表名+字段名+字段类型+少量样本值，返回字段语义匹配对 + 每对推荐的相似度算法
4. **关系计算**：NumPy 向量化执行全量比较——外键追踪 → 精确值相等 → 相似度矩阵计算 → 继承关系解析（基于 class_name 字符串前缀树）→ 合并多重关系为单边
5. **图谱生成**：组装 Graph 对象（nodes + edges），通过 WebSocket 推送完成事件，前端 D3 forceSimulation 渲染

### API 契约

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/tables` | GET | 返回数据库所有表名列表 |
| `/api/tables/{table_name}/fields` | GET | 返回指定表的所有字段名和类型，标记 class_name 候选字段 |
| `/api/analyze` | POST | 提交分析任务：`{tables: [{name, fields: []}], class_name_field?: string}`，返回 `{task_id}` |
| `/ws/analyze/{task_id}` | WS | 推送分析进度：`{phase: int, message: string, progress: float}` + 完成时 `{graph: {nodes, edges}}` |
| `/api/export/{task_id}` | GET | 返回完整 JSON 快照（graph + raw_data + config + layout） |

### 节点与边数据结构

节点的核心属性：唯一标识符（由表名+主键值组合生成）、来源表名、class_name、所有字段值、度数（关联数）、布局坐标

边的核心属性：源节点标识、目标节点标识、关系标签列表（按发现来源排序：FK > 值相等 > 语义匹配 > 继承）、置信度分数（0.0–1.0，确定性来源为 1.0，语义层由 AI 算法给出）、关系方向

### 前端模块划分

- **TableSelector**：表列表 + 多选勾选 + 数量上限提示
- **FieldSelector**：按表分组展示字段，class_name 自动标记并强制选中，其余字段多选 + 全选
- **AnalysisLauncher**：校验选择（至少 1 张表，class_name 必选）→ 启用"开始分析"按钮
- **ProgressIndicator**：WebSocket 连接组件，展示当前阶段 + 进度条 + 阶段描述文本
- **GraphCanvas**：D3 forceSimulation 核心渲染层，承载所有图谱交互
- **NodeDetailPanel**：右侧抽屉面板，展示双击节点的完整数据
- **StrengthFilter**：底部滑块控件，实时调节边的显示阈值
- **ExportButton**：导出当前图谱为 JSON 下载

### 前端状态管理

Zustand store 单例管理全局状态：当前阶段（选择/分析中/完成/错误）、选中的表与字段、WebSocket 连接状态、图谱数据（节点+边）、悬停/选中节点 ID、置信度阈值、详情面板开关

### 错误处理

所有异常路径返回友好中文提示 + 操作建议。三类关键异常：数据库连接失败（检查 .env）、AI API 不可用（稍后重试）、分析超时（减少数据量重试）

### 空值处理

NULL 值不参与任何关系匹配，两个 NULL 不视为相等，与所有其他值也不匹配

## Testing Decisions

### 测试原则

只测试外部可观测行为，不测试实现细节。每个测试从输入到输出，不依赖内部状态。

### 测试接缝与层级

**接缝 1：HTTP/WS API（系统测试）**
- 测试所有 REST 端点的请求/响应契约
- 测试 WebSocket 的进度消息序列（阶段顺序、进度递增、完成时的 graph 结构）
- 测试异常路径的错误响应格式和状态码
- Mock 外部依赖：MySQL 连接（用 SQLite 内存库替代）、DeepSeek API（用 fixture JSON 替代）

**接缝 2：AI 决策者模块（单元测试）**
- 纯函数接口：`decide_matches(tables: list[TableSchema]) -> list[FieldMatchDecision]`
- 测试：上下文感知的字段匹配（同名但不同表应分开）、算法推荐、无匹配时的空列表返回
- Mock DeepSeek API 调用

**接缝 3：关系计算引擎（单元测试）**
- 纯函数接口：`compute_relationships(records: dict[str, list[dict]], decisions: list[FieldMatchDecision]) -> Graph`
- 测试：外键关系检出、精确值相等检出、继承关系检出、多重关系合并、置信度计算、孤立节点处理

### 前端测试

- 组件渲染测试：TableSelector 勾选交互、FieldSelector 字段列表渲染、StrengthFilter 滑块值变化
- 集成测试：完整用户流程——选择表 → 选择字段 → 开始分析 → 图谱呈现（mock 后端 API 和 WebSocket）

## Out of Scope

- 参数调整重新生成（修改表/字段/AI 参数后重新分析）
- 节点和边的文本标注、状态标记（"已确认"、"忽略"）
- 手动创建/删除关系连线
- 表内关系发现（同一张表的记录之间的关联）
- 边数量渲染上限保护（当前数据规模（1000 行/表）暂不需要）
- AI 相似度算法选项池的完整扩展（MVP 使用字符串编辑距离 + 数值差值比例）
- 继承关系发现的确定性规则优化（MVP 基于 AI 推断 + class_name 前缀匹配）
- JSON 导入恢复（仅支持导出）

## Further Notes

- 分析执行是 CPU 密集型操作（全量笛卡尔积），建议 FastAPI 使用后台任务队列（`BackgroundTasks` 或 `asyncio.create_task`）避免阻塞
- WebSocket 连接在分析完成后可短时间保持以推送最终结果，之后由前端主动关闭
- D3 forceSimulation 在 10000 节点量级下性能可接受，但需注意力导向布局的计算在 requestAnimationFrame 中进行，初次布局需数秒 tick 稳定
- 该项目的领域术语表和后续 ADR 将维护在 `CONTEXT.md` 和 `docs/adr/` 中
